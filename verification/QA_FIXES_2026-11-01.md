# QA bug repairs — 1 November 2026

## Changes

| Reported behavior | Repair |
| --- | --- |
| Account creation has no password visibility control | Reusable accessible Show/Hide password inputs on registration, login and reset. Native selection, clipboard paste/copy and password-manager autocomplete remain available. |
| User Governance duplicates the Command Center | User directory, role/access controls and pagination render and fetch only in the dedicated User Governance tab. |
| Settings/profile links do not work | Dedicated Settings route linked from the profile, menu and role sidebar. Light/dark appearance and expanded/collapsed desktop navigation persist in this browser. Profile, courses and analytics share the correct role navigation. |
| Password editing is missing | Authenticated password change verifies the current password, validates the new password, hashes it, clears outstanding reset links and prevents concurrent overwrites. Rate limiting applies per authenticated user. No database migration is needed. |
| Three course-joining buttons on one page | One Join Course entry point, including the empty state, opens the existing code dialog. |
| New educator topics remain stale for learners | Enrolled-course counts and course topics refresh on focus, visibility, reconnect and every 15 seconds while visible. Background updates preserve the page during loading, display failures, and remove topic links when access is revoked. Late enrollment responses cannot replace a different course after navigation. Draft-course topic publication rules remain enforced. |
| Edited grades and pass/average rates disagree | Shared metrics use the published teacher percentage, including a valid zero; completed topic exams retain automatic grading. Pending reviews and active attempts are excluded from score/pass denominators. Both educator summaries, course charts and learner analytics use the same rule and refresh while open. Reads are batched and paginated. |
| Face monitoring fails to recover or report prolonged absence | Failed model loads can be retried. Cancelled camera requests release late streams. Missing/turned-away frames share one absence episode, with a 2-second grace period and recovery after three consecutive valid frames. Operational model/device errors show unavailable rather than fabricated violations. |
| Tab-switch violations disappear if the learner never returns | The event is queued immediately when the document becomes hidden. Existing durable, account-bound event delivery retries it and the backend retains idempotency and configured event thresholds. |

Pass rate is the percentage of released results with a final grade of at least
60%, retaining the application's existing threshold. Average score is the mean
of those released percentage grades. A missing denominator displays
Pending/No released results instead of an invented 0%.

## Verification

Final local results: 44 backend suites / 421 tests, 74 disposable database
contract/migration checks, and 30 frontend regression tests passed. Frontend lint,
type checking and both production builds passed. Browser fixtures passed all
7 general QA scenarios, 3 grade/analytics scenarios and 4 camera scenario groups.

Run from the named directory:

```text
backend:  npm test -- --runInBand
backend:  npm run build
backend:  npm run test:database
frontend: npm run lint
frontend: npm run typecheck
frontend: node --experimental-strip-types --test verification/*.test.mjs
frontend: npm run build
```

The backend suite covers password changes, grading-service persistence, final
grade zero, review visibility, pass boundaries, pagination, course authorization
and existing monitoring persistence. Frontend regressions cover camera state,
model retry, cancelled acquisition and durable event delivery, alongside existing
session, submission, hosting and exam-save checks.

For browser fixtures, build and run the local frontend preview on port 4173.
Use the separate Playwright installation and optional Chrome path described in
[README.md](README.md), then run from the repository root:

```text
node verification/qa-regressions-browser.mjs
node verification/analytics-grades-browser.mjs
node verification/face-detection-browser.mjs
```

The first script exercises registration clipboard behavior, persisted settings,
password success/failure, separate admin user governance, joining a course,
topic/count refresh, revoked access, delayed enrollment navigation and immediate
hidden-tab reporting. The second exercises educator and learner grade updates
through the real UI with intercepted API fixtures. The third mounts the actual
React camera hook with Chrome's synthetic webcam and deterministic model output,
including StrictMode cleanup and failure recovery.

All browser account/API responses are fixtures; no real credentials, grades,
enrollments, database settings or records are changed. Synthetic camera results
verify lifecycle and event logic, not accuracy on real people. Use the physical
camera/browser/lighting checks in
[browser-proctoring-limits.md](../docs/browser-proctoring-limits.md) on staging
before declaring the deployed camera experience verified.

The existing 60-second camera fallback completes through the ordinary
submission endpoint, so its stored submission reason remains the ordinary
student reason. This repair does not change that metadata contract. Configured
violation-limit submissions retain the backend's authoritative automatic reason.
